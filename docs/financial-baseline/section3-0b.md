Fixture rows are synthetic, within one selected calendar year: validated POS ₱1,000.10; validated rental ₱500.20; membership fee ₱200.00; membership-sourced share capital ₱1,500.00; Test POS ₱300.00; unposted Active expense ₱75.00; posted Active expense ₱400.30; Voided income ₱100.00; Reversed income ₱200.00; Active reversal adjustment −₱200.00; and an Active approved POS entry of ₱600.00 linked to a Pending payment.

The patronage repository exposes the JS Number intermediate `2400.2999999999997` for the synthetic ₱1,900.10 + ₱500.20, while its final net is rounded to two decimals. `toCentavos` on decimal strings gives 30 for ₱0.10 + ₱0.20. This observation is not a claim that every displayed total or payout is wrong.

Ambiguous/unmatched items must remain visible and cannot be assumed to consume no budget. No actual budget, balance or assignment was inspected or changed here.

## Evidence, exclusions and follow-up ownership

- `financial-semantic-baseline.test.ts` and `budget-legacy-baseline.test.ts` exercise pure functions or the real services with mocked query boundaries. The tests assert **existing behavior**, not proposed payout changes. SQL views and other SQL fragments were not executed.
- S3-1 / PR 1B: approved budget attribution/cutover, schema-failure behavior and real disposable-MySQL concurrency tests; require the owner's pending-commitment decision before activating policy.
- S3-4 / PR 4A–4C: define equivalent operational report populations, legacy view/report semantics, snapshots and authorized regression tests. The existing diagnostic helper's pending-payment and patronage-adjustment differences need separately reviewed correction; no live distribution calculation was modified here.
- Section 4 / source owners: verify POS/rental payment, refund/reversal, amount/receipt matching, gateway authority and duplicate identity through their established contracts. A receipt-generation failure is not itself proof of an unpaid payment.
- PR #6/#7: retain True/Associate separation, ₱15,000 cap, membership obligations, interest/dividend entitlements and annual eligible-equipment-rental 3% patronage. Any payout-formula change requires separate approval.
- Full MySQL `DECIMAL`, joins, duplicate/refund propagation, stored view output, timezone/session effects, historical balances and ownership are **not verified** by these fixtures. `npm run db:check` is only table-presence checking and was not run. No production/staging database connection, migrations, data repairs or deployment were performed.
