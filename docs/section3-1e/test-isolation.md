# PR 1E test isolation

`npm run test:api`, `npm run test:paymongo-core` and `npm run test:records` use `scripts/isolated-tests.mjs`. It launches test workers with a small OS environment allowlist, fresh temporary local storage, synthetic database settings and no inherited credentials or opt-in MySQL flags. Node test workers do not load `server/.env`; the application pool rejects database operations and the storage factory rejects S3 or a non-temporary root. Legacy public-upload fallback is disabled in test workers to avoid reading or deleting local application files.

These guards apply to the normal test commands and application pool/storage factory, not to arbitrary direct `mysql2` clients, direct S3 clients, child processes, or every possible network request. They are not a network sandbox. Existing opt-in SQL suites are intentionally skipped by the normal runner; they require separately provisioned disposable MySQL, verified server identity and explicit review of each test before running. The evidence-only suite can be selected via `node scripts/isolated-tests.mjs --evidence-mysql <port> <synthetic-datadir> server/src/modules/financial-evidence/receipt-evidence.mysql.test.ts`; it verifies the server port and exact datadir before creating a random synthetic database. Never pass production credentials to a test process. `test:records` may discover zero tests and is not evidence of coverage.

The previous S3-configured test attempts have no verified provider audit evidence in this workspace. No conclusion about external requests is possible from the test results alone; do not access live S3 to investigate.
