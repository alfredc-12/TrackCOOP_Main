Revision `d9a7240d6f720636602df9418d722d9bff460d2b`, branch `feature/section3-financial-evidence-1e`. The untracked `src/lib/desktop.ini` predated this work and was left intact.

The currently implemented checks run with `npx.cmd playwright test --config playwright.database-evidence.config.ts` after starting the isolated services. This is not a complete implementation of the 54 proposed scenarios. Set `PLAYWRIGHT_EVIDENCE_RUN` to a new directory name matching `database-[a-z0-9-]+` before each run so reports are not overwritten. `database-complete` contains the latest full run: 32 Playwright tests, 29 passed and 3 failed. Three tests capture screenshots rather than assess proposed scenarios; one of these failed on the 404 member route. The Word report distinguishes full scenario passes from partial checks.

The environment used MySQL 8.4.3 at `127.0.0.1:33327`, database `trackcoop_evidence_synthetic`, and data directory `scratch/playwright-isolated-mysql/data`. Before use, the port, data directory and database name were verified. Its initial database list contained only MySQL system databases. The frontend ran on `127.0.0.1:3217` and API on `127.0.0.1:3218`. The API was launched from `scratch/playwright-isolated-mysql` so it did not load `server/.env`, with local storage, `EMAIL_DELIVERY=disabled` and `PAYMONGO_ENABLED=false`. The owner's remote development database and PayMongo configuration were not used.

Setup used `server/database/TrackCOOP_MAIN_Database.sql` on the new database. `testing_data_and_admin_settings.sql` initially failed on sector enums; a test-only copy replaced `Rice Farming` with `Rice`, `Fisherfolk` with `Fishery`, and `Vegetable Farming` with `High-value crops (gulayan)`. The original file was not edited. The seasons migration `20261027_seasons_and_budget_controls.sql` was applied. The API's login rate limit was set to 100 per minute only for this isolated test server after an earlier run encountered 429 responses. Synthetic accounts and passwords are defined by the repository test seed.

To recreate the environment, initialize a **new empty** MySQL data directory using the installed MySQL 8.4 `mysqld --no-defaults --initialize-insecure`, start it bound only to loopback on a free dedicated port, and verify `@@port`, `@@datadir`, and the empty database list before importing anything. Create only the named synthetic database and import the schema, adapted seed, and seasons migration described above. Start the API from an empty test working directory with `DB_HOST=127.0.0.1`, `DB_PORT=33327`, `DB_NAME=trackcoop_evidence_synthetic`, `DB_USER=root`, `DB_PASSWORD` empty, `DB_SSL=false`, `API_PORT=3218`, `AUTH_LOGIN_RATE_LIMIT=100`, `AUTH_LOGIN_RATE_WINDOW_MINUTES=1`, `FRONTEND_URL` and `CORS_ALLOWED_ORIGINS` set to `http://127.0.0.1:3217`, `STORAGE_DRIVER=local`, `LOCAL_STORAGE_ROOT` set to an isolated directory, `EMAIL_DELIVERY=disabled`, and `PAYMONGO_ENABLED=false`. Start Next on port 3217 with `NEXT_PUBLIC_API_URL=http://127.0.0.1:3218`. The database helper refuses an unexpected port, schema, or data directory. Do not use this test configuration on a shared or production server.
