# Reproduction and safety controls

The baseline revision is `b68329235438e2f7986d898089beaf64e2b347f4`. The owner confirmed the configured `trackcoopdb_main` RDS instance is a dummy development database. Reconfirm the exact target and its dependencies before any later test; the scripts' schema-name and RDS-host guards alone do not prove development-only status. Do not use these scripts against production or against an instance serving live operations.

Use a fresh workspace with empty JMeter output directories; `run-formal.py` intentionally refuses to overwrite existing runs or snapshots. Preserve all original results, including `invalidated/`. The test requires Apache JMeter 5.6.3 and a Java 17 runtime in the locations expected by the driver; verify the distributions against their publishers' checksums. The local Python charting environment also needs `matplotlib`, `python-docx`, and optionally `psutil`.

1. Inspect `server/.env` privately and verify the owner-approved development-only database, MySQL version, schema and migration state. Never copy credentials into the evidence directory. `node evidence/jmeter/scripts/inventory-development-db.cjs` prints only metadata and aggregate role counts.
2. Ensure the activity-management migration is already present. `scripts/activity-preflight.cjs` is read-only. The one-time `apply-activity-dev.cjs` was used on the specifically confirmed dummy instance after its additive DDL and prerequisites were inspected; it refuses partially applied or unexpected schemas. Do not rerun blindly.
3. `node evidence/jmeter/scripts/create-fixtures.cjs` creates exactly 20 new test-owned accounts and 12 synthetic profiles in a transaction, storing random passwords only in ignored `scratch/jmeter-private/users.csv`. It refuses to overwrite an existing CSV. `node evidence/jmeter/scripts/prepare-referrals.cjs` initializes only missing referral codes on those profiles. These are persistent test records; coordinate their retention or cleanup with the database owner. Never delete or reset unrelated records.
4. From the repository root, run `python evidence/jmeter/scripts/build-plan.py`, then start `node --import tsx evidence/jmeter/scripts/local-api.mjs`. The launcher must print its loopback listening message after its configuration and outbound guard checks. It reads only database settings from the private development environment, runs from a private working directory to prevent dotenv reload, disables payment and email, uses local storage, restricts routes and outbound connections, and maps validated virtual-user slots to reserved synthetic IP addresses. No external payment, notification or financial-write route is allowed.
5. Run a short calibration and verify all ten groups, role-based sessions, response assertions, safe negative assertions, generated HTML, and before/after integrity snapshots. Do not count calibration as a formal run.
6. With a fresh output tree, `python evidence/jmeter/scripts/run-formal.py` runs the nine independent CLI executions and records snapshots and a 300-second steady-state summary for each. It uses a 60-second ramp and a five-second excluded tail, and stops for setup, thread-coverage, dashboard or integrity problems. A genuine HTTP/application failure stays in the original samples and is not automatically retried. The local monitor may be started separately with `scripts/monitor-resources.py` and stopped with the ignored `scratch/jmeter-private/stop-monitor` flag.
7. `scripts/compile-evidence.py` calculates summaries and figures from the completed JTL files; `scripts/build-report.py` generates the Word report only after all nine verified run records exist. Inspect the report visually and run `scripts/finalize-manifest.py` after final changes.

The JMeter plan reads each private CSV row once using a Groovy preprocessor; it does not use the standard JMeter CSV Data Set element. It saves HTTP samples and separate `TX_Jxx` transaction summaries. HTTP acceptance calculations exclude setup, transaction summaries, ramp-up, the tail and boundary-crossing samples. See `methodology.md` for formulas, transaction treatment and interpretation limits.
